新的开始：mojimoon.top

欢迎来到本博客！你也可以点击左上角头像查看个人简介。

总而言之，在建站三年半以后，笔者终于意识到拥有一个独立域名的重要性：没有独立域名，就永远只能使用 GitHub Pages 的二级域名，无法使用 CDN 代理，这让国内的访问速度非常慢。

于是在今天，笔者启用了独立域名 mojimoon.top，并将博客迁移到 blog.mojimoon.top。

建站历程

2023 年 1 月 14 日

cryovit.github.io 建立。

使用 Hexo 的 Stellar 主题，部署在 GitHub Pages 上。

2023 年 7 月 30 日

迁移到 mojimoon.github.io。

2024 年 12 月 6 日

迁移到 mojimoon.github.io/blog。

2025 年 4 月 22 日

使用 JSDelivr CDN 加速静态资源。

2026 年 8 月 14 日

启用新域名 mojimoon.top，本站迁移到 blog.mojimoon.top。

使用 Cloudflare CDN 代理，JSDMirror CDN 加速静态资源。

一些趣事

在选这个域名的过程中，笔者考虑过多个注册商。这其中，阿里云没什么优惠，腾讯云比较优惠、价格和 Namesilo 接近，但是作为一个国内平台，腾讯云上注册域名需要备案。虽说笔者不是不能接受备案，但这就需要等待一点时间了，再加之价格也没有优势，最终选择了 Namesilo。

Namesilo 的价格着实便宜，.top 域名首年 1.88 美元，续费 4.88 美元，还送了免费的 Whois 隐私保护。除此之外，Namesilo 支持支付宝付款，甚至可以用支付宝自动续费，可以说很是惊喜了。当然，与之相对的，Namesilo 的后台界面也着实廉价，并且 UI 还不统一，但是问问 AI 还是能够理解怎么操作的。

使用教程

要让你的 GitHub Pages 使用独立域名并启用 Cloudflare CDN 代理，操作起来并不麻烦。其实问 AI 全都可以解决，不过笔者还是写一篇教程，方便大家（主要是自己）以后查阅。

1. 将 Cloudflare 作为 CDN 代理

  1. 注册或登录 Cloudflare。顺便一提，右上角头像下拉菜单是可以切换语言到中文的（虽然翻的多少有点奇怪）。
  2. 添加你的域名，比如 mojimoon.top，选择免费计划。
  3. Cloudflare 会先扫描你的 DNS 记录，但是新购买的域名应该是没有的，继续。
  4. Cloudflare 会给你提供两个 nameserver，比如：
  1. 前往域名注册商的管理界面，将原有的 nameserver 替换为 Cloudflare 提供的 nameserver。
  2. 回到 Cloudflare，点击继续，等待 Cloudflare 检测 nameserver 是否生效。这个过程最多要 48 小时，但是一般几分钟就能生效。

等到 Cloudflare 显示 Your domain is being protected by Cloudflare（你的域名正受 Cloudflare 保护）时，可以进入下一步。

2. 在 Cloudflare 上添加 DNS 记录

点击左侧导航的 DNS > Records (DNS > 记录)，然后“添加记录”。为每个子域名添加一条 DNS 记录，类型为 CNAME，内容为 username.github.io，其中 username 是你的 GitHub 用户名。

TypeNameContentProxy statusTTL
CNAMEblogmojimoon.github.ioDNS only（灰色云）Auto
CNAMEwenkumojimoon.github.ioDNS only（灰色云）Auto
CNAMEbrotatomojimoon.github.ioDNS only（灰色云）Auto

需要说明的是，先用 DNS only（灰色云），等到 GitHub Pages 签发 SSL 证书后（下面会讲到），再改为 Proxied（橙色云）。

此外，我还要启用 mojimoon.top 存放个人主页。尽管现在 Cloudflare 已经允许给根域名添加 CNAME 记录，但是一般还是使用 www.mojimoon.top 作为首页，然后让根域名 mojimoon.top 重定向到 www.mojimoon.top。添加以下 DNS 记录：

TypeNameContentProxy statusTTL
CNAMEwwwmojimoon.github.ioDNS only（灰色云）Auto
A@192.0.2.1Proxied（橙色云）Auto

然后点击左侧导航的 Rules > Overview（规则 > 概览），直接应用模板 Redirect from root to WWW（从根重定向到 WWW），启用 Preserve query string（保留查询字符串）即可。

手动添加：

  • If incoming requests match… Wildcard pattern
  • Request URL: https://mojimoon.top/*
  • Then, Target URL: https://www.mojimoon.top/${1}, Status code: 301
  • Preserve query string: On

3. 在 GitHub Pages 上启用自定义域名

  1. 打开 GitHub 仓库，点击 Settings > Pages，在 Custom domain 输入你的域名，比如 blog.mojimoon.top，然后点击 Save。
  2. GitHub 可能会在仓库根目录下创建一个 CNAME 文件：
  1. 等待 GitHub Pages 签发 SSL 证书，这个过程大概需要几分钟，然后勾选 Enforce HTTPS。
  2. 等到 GitHub Pages 显示 Your site is published at https://blog.mojimoon.top/，就可以在 Cloudflare 上将 DNS 记录的 Proxy status 改为 Proxied（橙色云）。

常见问题：

显示：Enforce HTTPS — Unavailable for your site because your domain is not properly configured to support HTTPS。

解答：说明你在 Cloudflare 已经启用了橙色云。先改成灰色云，然后回到 GitHub Pages 并刷新，等待 Enforce HTTPS 可用后，再改回橙色云。

新增应用

除了迁移博客和已有的项目之外，我还新增了 mojimoon.top 作为个人主页，方便链接到我的各个项目和 GitHub 主页。

此外，Cloudflare 免费计划中包含着相当多的计算资源（包括 Workers、Pages、D1 等），因此我部署了一个 CloudPaste 作为一个轻量级的文件中转站/分享站。

使用 GitHub Pages + Cloudflare 部署的指南可以参考 官方文档，写的十分详细，包教包会。

推荐根据教程，完成环境配置和一体化部署，然后回到 Cloudflare，点击左侧 Compute > Workers & Pages（计算 > Workers 和 Pages），点击上方的 Domains（域），禁用 workers.dev 结尾的默认域名，并且在下面添加自定义域名的子域名 paste.mojimoon.top，即完成配置。
